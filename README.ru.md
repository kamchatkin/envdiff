# envdiff

[English version](README.md)

Небольшая кроссплатформенная утилита на C для объединения `.env.example` с
рабочим `.env`. Она работает как Unix filter: по умолчанию готовое содержимое
выводится в стандартный поток, а входные файлы не изменяются. Поддерживаются
Linux, macOS и Windows.

Существующие значения не извлекаются, не сравниваются и не изменяются. Если ключ
уже существует, его значение всегда остаётся прежним.

## Сборка

Требуются CMake 3.20 или новее и компилятор C11: GCC/Clang на Linux, Apple Clang
на macOS или MSVC на Windows.

Linux и macOS:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
```

Windows, PowerShell из Visual Studio Build Tools:

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Windows-бинарник будет находиться в `build/Release/envdiff.exe`, Unix-бинарник —
в `build/envdiff`.

На Linux и macOS также можно использовать Makefile:

```bash
make
make check
```

Makefile выводит размер результата только для информации. Ограничения, при
котором сборка завершается ошибкой из-за размера, нет.

Установка в `~/.local/bin`:

```bash
make install
```

Каталог `~/.local/bin` должен присутствовать в `PATH`.

## Автоматические сборки

GitHub Actions собирает и тестирует программу на Linux, macOS и Windows. Архивы

## Использование

Порядок двух позиционных аргументов всегда один и тот же:

```text
envdiff [-c] [-f] [-i | -o FILE] <example.env> <current.env>
```

1. `<example.env>` — шаблон с ожидаемыми ключами и комментариями;
2. `<current.env>` — рабочий файл, существующие значения которого сохраняются.

В качестве защитной проверки `envdiff` отказывается использовать как
`<current.env>` файл, базовое имя которого содержит `example` без учёта
регистра. Обычно это означает, что позиционные аргументы перепутаны местами или
переданы два example-файла. Названия директорий при этой проверке не
учитываются. Если такое имя рабочего файла выбрано намеренно, проверку можно
отключить флагом `-f` или `--force`:

```bash
envdiff -f template.env current.example.env
```

`FILE` после `-o` или `--output` является аргументом опции и задаёт выходной
файл. Это не один из двух позиционных аргументов. Опции можно указывать до или
после позиционных аргументов. В примерах ниже выходная опция находится в конце,
чтобы порядок читался одинаково: `example → current → output`.

Вывести объединённый `.env` в стандартный поток, не изменяя входные файлы:

```bash
envdiff .env.gateway.example .env.gateway
```

Записать результат перенаправлением в другой файл:

```bash
envdiff .env.gateway.example .env.gateway > .env.gateway.merged
```

Атомарно обновить рабочий файл:

```bash
envdiff .env.gateway.example .env.gateway -i
```

`-i`/`--in-place` означает, что выходным назначается сам рабочий файл. Утилита
полностью читает его до атомарной замены. Эквивалентная полная команда:

```bash
envdiff .env.gateway.example .env.gateway -o .env.gateway
```

Записать в другой файл без перенаправления shell:

```bash
envdiff .env.gateway.example .env.gateway --output .env.gateway.merged
```

Показать структурную разницу без изменения файлов:

```bash
envdiff .env.gateway.example .env.gateway -c
```

`-c` — короткая форма `--check`.

В отчёте используются обозначения в стиле `diff`:

- `+` — отсутствующий ключ или комментарий из `.example`;
- `-` — ключ, который есть только в рабочем файле и требует проверки перед
  удалением; его значение заменяется на `<value hidden>`;
- строка ключа без префикса — контекст для отсутствующего комментария, значение
  этого ключа не сравнивается.

Для ключей с `+` выводятся полные строки из `.example`, чтобы их можно было
добавить вручную. Значения ключей с `-` скрываются: для ручного удаления
достаточно имени ключа. Значения ключей, присутствующих в обоих файлах,
по-прежнему не сравниваются.

```text
Missing from .env:

+ # Request timeout
+ REQUEST_TIMEOUT=30

Only in .env (review before removing):

- # Legacy option
- LEGACY_TOKEN=<value hidden>
```

`--check` возвращает код `1`, если найдены отсутствующие ключи/комментарии или
ключи только в рабочем файле, и `0`, если структурной разницы нет.

> **Внимание:** `--check` выводит значения из `.env.example` и комментарии из
> обоих файлов. Значения рабочих ключей скрываются, но комментарии — нет. Не
> храните секреты в комментариях и `.env.example` и не публикуйте такой вывод в
> открытых CI-логах.

Нельзя перенаправлять вывод в один из входных файлов:

```bash
# Неправильно: shell очистит файл до запуска envdiff.
envdiff .env.gateway.example .env.gateway > .env.gateway
```

Для безопасного изменения этого же файла используйте `-i` или
`-o .env.gateway`.
Успешная фильтрация и запись через `-i`/`-o` не выводят служебных сообщений.
Отчёт `--check` направляется в `stdout`, ошибки — в `stderr`.

Версия программы:

```bash
envdiff --version
```

Утилита не заменит существующий `NATS_URL=nats://...` на
`NATS_URL=tls://...`: значение существующего ключа нужно менять вручную.
